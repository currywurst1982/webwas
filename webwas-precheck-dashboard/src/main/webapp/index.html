    재설치가 필요한 에이전트

    대시보드의 점검 스크립트나 에이전트가 새 버전으로 바뀌었는데, 아래 서버에는 아직 예전 것이 설치되어 있습니다. 서버마다 sudo -i 로 root 가 된 뒤 아래 명령을 붙여 넣으세요. 기존 설정(주소·이름·토큰·로그 경로)을 그대로 읽으므로 토큰을 새로 발급할 필요가 없습니다. 끝나면 1~2분 안에 이 목록에서 빠집니다.

      에이전트 접속 주소

      [에이전트 추가]·[토큰 재발급] 때 나오는 설치 명령에 들어갈 대시보드 주소입니다. 점검할 서버에서 접속하는 주소가 브라우저 주소와 다르면 (예: 관리자는 https 로, 서버는 http://대시보드IP:8580/webwas-precheck 로) 여기에 적어 두세요. 비우면 지금 브라우저 주소창의 주소를 씁니다.

      에이전트 관리

      상태에이전트마지막 접속마지막 점검점검 제품 · 버전다음 자동 점검주기스크립트

      에이전트는 1분마다 대시보드에 점검 차례인지 묻습니다. [지금 점검]을 누르면 1분 안에 시작하며, 점검 시간은 서버에 따라 수 분 걸릴 수 있습니다. 화면은 30초마다 자동으로 갱신됩니다.

      제품별 최신 버전

      12시간마다 공식 배포 목록에서 자동으로 확인합니다. Tomcat 은 지원 중인 브랜치(예: 11.0 / 10.1 / 9.0)마다 최신 버전을 따로 비교하며, 목록에 없는 브랜치는 "지원 종료"로 표시합니다. Nginx 는 stable 브랜치 최신만 기준으로 씁니다(그보다 새 mainline 은 최신으로 봄).

      CVE 목록 자동 업데이트

      제품사용 중인 목록CVE마지막 확인

      출처: Apache = Apache 보안팀 공식 CVE JSON(httpd.apache.org), WildFly·Tomcat = OSV 취약점 DB(osv.dev, GitHub Advisory 등급). 에이전트는 점검 직전에 이 목록을 받아 스크립트에 넘기므로 점검 서버에 인터넷이 없어도 됩니다(대시보드 서버만 접속 가능하면 됨). Apache 의 새 CVE 는 제목의 mod_xxx 로 필요 모듈을 추정하고, 못 찾으면 '항상 해당(core)'으로 판정합니다. [받기]로 받은 파일은 sudo bash 제품_precheck.sh -C 파일 처럼 직접 실행할 때 쓸 수 있습니다.

      화면 모드

      상태항목범위사유등록만료

      서버 상세 창 → 점검 결과의 [위험]·[주의] 항목에서 [예외 처리]로 등록합니다(관리자). [4] 침해 흔적의 [위험]은 예외 처리할 수 없습니다. 만료된 예외는 효력이 없으며 [해제]로 정리할 수 있습니다.

      IP 자동 그룹 규칙

      서버 IP 가 규칙에 맞으면 자동으로 그 그룹으로 묶입니다. 새로 등록하는 서버도 IP 만 맞으면 바로 묶입니다. 에이전트에 그룹을 직접 지정했으면 그쪽이 우선합니다. 위에서부터 먼저 맞는 규칙이 적용됩니다.

      순서IP 패턴그룹

      패턴: 10.10.10.0/24(CIDR) · 10.10.*(10.10.*.* 과 같음) · 10.10.10.10(정확한 IP). IPv4 전용. 판정은 리포트에 기록된 서버 IP(없으면 에이전트 접속 IP)로 합니다.

      점검 기록 초기화

      누르면 먼저 지워질 건수를 보여 주고, 초기화 라고 직접 입력해야 실행됩니다. 지운 기록은 바로 없어지지 않고 데이터 폴더의 reports-trash 로 옮겨져 30일 동안 보관됩니다(되살리기: 그 폴더의 파일을 reports 폴더로 다시 옮기기). 에이전트 등록·토큰·사용자·설정은 지우지 않습니다. 서버 1대의 이력은 서버 상세 창, 에이전트 1대의 기록은 에이전트 관리의 [기록 초기화]로도 지울 수 있습니다.
